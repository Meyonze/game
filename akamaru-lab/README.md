# AKAMARU — real-time character study

An independent, interactive 3D prototype for Meyonze Games. Open `index.html` over HTTP. It reuses the repository's vendored Three.js 0.170.0 (MIT, license in `../neon-rift-duel/vendor/THREE-LICENSE.txt`). No build, network model downloads or gameplay backend required. Google Fonts have system fallbacks.

The character is newly modeled in code with ellipsoids, beveled shaped armor, a continuous striped tail surface, face details, a scarf and a curved sword. It uses MeshToonMaterial with a three-step gradient and inverted-hull screen-space outlines. It is a simplified interpretation of the generated concept, not a claim to reproduce that image's fidelity. The procedural hierarchy animates breathing, running, scarf/tail movement and a two-handed diagonal cut with a lowered, staggered guard, a shoulder-side preparation, a short right-foot step, a settled follow-through and recovery. Both arms use analytic two-bone IK on fixed handle grips; the cutting edge leads the authored blade arc. A waist-level chest pivot separates torso rotation from the hips. Both knees remain bent in guard, the feet stay planted during breathing, and the trunk shifts forward during the cut. The rear foot stays planted through the cut, and sword movement never comes from independently spinning the wrist. This is a separate character prototype; DUEL has not been replaced.

Controls: drag to orbit, wheel/pinch to zoom, front/side/back/follow views, idle/run-in-place preview, F or Space or the strike button to slash, WASD/arrows to move. Follow view exposes touch direction buttons. Outline width and toon/smooth shading can be compared live. A 0.35× playback toggle exposes the attack phases. A pose pause freezes motion while keeping orbit and view buttons usable; pressing attack resumes playback. Moving is locked for the full attack, including slow playback. Hidden tabs pause updates; WebGL initialization and context-loss errors appear onscreen.

Validation: `node akamaru-lab/test.mjs` checks actual geometry, animation transforms, ground contact, outline controls and asset references. `node akamaru-lab/controller-test.mjs` exercises the controller with a mock renderer/DOM. Geometry was also inspected using an offline Blender render of the same meshes. That render is not the browser's shader output. `node akamaru-lab/motion-test.mjs` checks both hand contacts, foot planting, cutting-edge alignment, a single descending stroke, settled follow-through, recovery continuity and 30/60/120 Hz timing. The stance revision was also inspected in headless Chromium with the real WebGL renderer (SwiftShader), including front/side/back views and attack poses. Automated pose tests are structural checks, not proof of martial-arts authenticity. Hardware GPU and real mobile-device performance remain unverified.
